# القرارات التقنية

الحالة: ✅ معتمد | 🟡 مقترح ينتظر موافقة | ❌ مرفوض

## نطاق المشروع ✅
- البداية: **صف/مدرسة واحدة**، ثم التوسع لبقية الصفوف إذا نجح التطبيق. التصميم يدعم التوسع من البداية (جدول schools/classes).
- **أندرويد أولاً** (APK). الكود يدعم آيفون لاحقاً دون إعادة كتابة.
- **كل شيء مجاني** قدر الإمكان.
- **تقسيم العمل**: المساعد يكتب كل الكود. صاحب المشروع يخطط ويفحص ويجرب، وينشئ الحسابات والمفاتيح (Supabase, Google AI, Firebase, Dropbox) ويربطها.
- **التنفيذ بخطوات** حسب `TASKS.md`، وليس عشوائياً.
- **الأدمن يرى كل شيء**: كل الطلاب المسجلين، درجاتهم، نشاطهم.
- **التطبيق مضبوط**: كل طالب معرَّف بحسابه، لا يدخل أحد دون موافقة الأدمن.

## 1. إطار عمل التطبيق ✅ React Native + Expo (TypeScript)
السبب: سريع في التطوير، تطبيق أصلي حقيقي، واجهة جميلة وسهلة، نفس لغة لوحة التحكم.
| الخيار | الحكم |
|---|---|
| Kotlin أصلي | ❌ أبطأ في التطوير، كود منفصل عن لوحة التحكم |
| HTML/CSS/JS داخل WebView | ❌ الكاميرا والإشعارات والدردشة وعدم الاتصال ضعيفة |
| Flutter | ❌ لغة Dart مختلفة عن لوحة التحكم |
| **React Native + Expo** | ✅ |

**أدوات الواجهة:**
- **Expo Router**: التنقل بين الشاشات. **Expo SDK 57**.
- ~~NativeWind~~ ← **مكونات خاصة بـ StyleSheet** (`apps/mobile/src/components/ui.tsx`) بألوان الهوية من `@saey/shared`. السبب: أقل اعتماديات وأقل مشاكل بناء، وتحكم كامل بالتصميم.
- **RTL مفروض** على كامل التطبيق + خط عربي واضح (مثل IBM Plex Sans Arabic أو Cairo).
- **مبدأ التصميم**: الطالب لا يحتاج أن يفكر — أزرار كبيرة، أيقونات واضحة، 3 نقرات كحد أقصى للوصول لأي شيء، وضع ليلي.
- **البناء**: EAS Build ← ملف APK.

## 2. لوحة التحكم ✅ React + Vite + TypeScript ← Firebase Hosting (كان Netlify — استُبدل، انظر ١٣)
- موقع للأدمن فقط، دخول محمي بصلاحية admin من قاعدة البيانات.

## 3. الخلفية ✅ Supabase (الخطة المجانية) + Supabase Storage للملفات (كان R2 — استُبدل، انظر ١٣)
- Postgres + المصادقة + Realtime (الدردشة) + Edge Functions + pgvector.
- الصلاحيات عبر Row Level Security.
- **الملفات الكبيرة** (الملازم PDF): Cloudflare R2 (10GB مجاناً، تحميل بلا رسوم نقل).
- **الصور** (صور شخصية، صور الدردشة): تُضغط في التطبيق قبل الرفع.
- **الفيديوهات**: روابط يوتيوب فقط.
- ⚠️ مشروع Supabase المجاني يتوقف بعد 7 أيام بلا نشاط ← مهمة مجدولة بسيطة (ping) تبقيه نشطاً.

## 4. المساعد الذكي ✅ Google Gemini API (الطبقة المجانية)
- النموذج: `gemini-2.5-flash` للأسئلة، و`gemini-2.5-flash-lite` للمهام الخفيفة (حدوده المجانية أعلى).
- الاستدعاء عبر Supabase Edge Function — المفتاح لا يوضع أبداً في التطبيق أو المستودع.
- RAG من المنهج (pgvector) + ذكر المصدر.
- **حد يومي لكل طالب** (قابل للتعديل من لوحة التحكم) + عداد استهلاك عام يظهر للأدمن.
- عند الوصول للحد: رسالة لطيفة «انتهى رصيدك اليوم، يتجدد غداً».

### ⚠️ حقائق مهمة عن Gemini (تم التحقق أكتوبر 2026)
1. **اشتراك Google AI Pro لا يعطي أي رصيد للـ API.** الاشتراك للتطبيق والمحادثة فقط؛ الـ API له طبقة مجانية منفصلة متاحة لأي حساب.
2. **الحدود المجانية لكل مشروع (Project) وليس لكل مفتاح**، وقد خفّضتها Google في ديسمبر 2025 (تقريباً 250–500 طلب/يوم لـ Flash، وأحياناً أقل).
3. **استخدام عدة حسابات لتجاوز الحدود مخالف لشروط Google** وقد يؤدي لحظر الحسابات (ومنها حساباتكم الشخصية). ❌ لن نعتمد عليه.
4. بيانات الطبقة المجانية قد تستخدمها Google لتحسين نماذجها ← لا نرسل بيانات شخصية للطلاب (الأسماء، الدرجات) للنموذج.
5. **الخطة البديلة** إذا كبر الاستخدام: الدفع حسب الاستخدام لـ Flash-Lite رخيص جداً (غالباً أقل من بضعة دولارات شهرياً لصف واحد).

**توفير الطلبات:** تخزين إجابات الأسئلة المتكررة، اختبارات ذاتية مولّدة مسبقاً وتُعاد، Flash-Lite للمهام البسيطة.

## 5. تصوير الأسئلة ← PDF/نص ✅
- الإصدار الأول: كاميرا expo-image-picker مع القص + ضغط بدقة عالية. (ML Kit Document Scanner مؤجل لأنه يحتاج مكتبة أصلية إضافية.)
- PDF من الصور يُنشأ في الخادم بـ pdf-lib، والنص يُستخرج بـ Gemini.
- استخراج النص العربي والمعادلات بـ Gemini Vision ← نص + LaTeX.
- الأدمن يراجع قبل النشر.

## 9. الهوية والتصميم ✅ (الاتجاه) — 🟡 (الاسم والألوان النهائية)
- **الخط: ثمانية (Thmanyah)** — Sans للواجهة، Serif Display للعناوين الكبيرة، Serif Text للقراءة الطويلة. الملفات في `assets/fonts/thmanyah/`.
- **الأسلوب**: مثل تطبيق ثمانية + إتقان التطبيقات العالمية (تلجرام، ديسكورد). بعيد تماماً عن «شكل تصاميم الذكاء الاصطناعي»: لا تدرجات لونية مبالغ فيها، لا ظلال كثيرة، لا أيقونات تعبيرية عشوائية. طباعة قوية، مساحات بيضاء، لون مميز واحد.
- **الثيم**: فاتح افتراضياً + غامق قابل للتبديل (ويتبع إعداد الهاتف تلقائياً).
- **اسم التطبيق ✅ «سعي»** — التفاصيل الكاملة للهوية في `05-brand.md`.

## 10. قرارات التنفيذ ✅ (الجلسة ١)
- **Monorepo** بـ npm workspaces: `apps/mobile` و `apps/admin` و `packages/shared`.
- **`packages/shared`**: منطق الدرجات والإعفاء + الأنواع + ألوان الهوية + تنسيق الأرقام العربية — مشترك بين التطبيق ولوحة التحكم، ومغطى باختبارات.
- **لوحة التحكم**: React 19 + Vite 7 + react-router 7، CSS خاص بمتغيرات الهوية (فاتح/غامق تلقائي).
- **قراءة الملازم**: تُحمّل وتُفتح بقارئ PDF في الهاتف (وتبقى محفوظة للقراءة دون إنترنت).
- **المعادلات**: KaTeX (داخل WebView في التطبيق، ومباشرة في لوحة التحكم).
- **فهرسة الملازم للمساعد**: Gemini File API + نسخ ١٠ صفحات في كل استدعاء + embeddings (768 بُعداً) في pgvector.
- **الإشعارات**: جدول `notifications` + مشغّلات pg_net ← دالة `push` ← Firebase مباشرة (انظر ١٢).
- **سجل العمليات**: مشغّل `audit()` يسجل عمليات الأدمن والمشرفين تلقائياً.

## 11. الحركة والويدجتات ✅ (الجلسة ١)
- **الحركة**: Reanimated 4 فقط (بلا مكتبات إضافية). العناصر الأساسية في `apps/mobile/src/components/motion.tsx`: `PressScale` (نابض اللمس)، `enter` (ظهور خفيف — أُلغي الدخول المتتابع للشاشات في الجلسة ٢)، `CountUp`، `Skeleton`، `tap()` (اهتزاز خفيف عبر expo-haptics). الحركة تحترم إعداد «تقليل الحركة» في الهاتف.
- **المقدمة**: `components/intro.tsx` — شاشة البداية الأصلية فارغة (صورة شفافة) والمقدمة ترسم الشعار ثم الاسم بالكشيدة. الضغط يتخطاها.
- **الويدجتات**: مكتبة `react-native-android-widget` (أندرويد فقط، لا تعمل في Expo Go). الملفات في `apps/mobile/src/widgets/`:
  - `data.ts` لقطة بيانات صغيرة تُحفظ في AsyncStorage وتُجلب من Supabase.
  - `views.tsx` التصاميم (فاتح/غامق)، `registry.tsx` الأسماء، `handler.tsx` يعمل في الخلفية كل ٣٠ دقيقة، `sync.ts` تحديث من داخل التطبيق.
  - نقطة الدخول `apps/mobile/index.js` تسجّل معالج الويدجت بعد `expo-router/entry`.
  - أسماء الويدجتات في `app.json` يجب أن تطابق `WIDGET_NAMES`.
  - عند تسجيل الخروج تُمسح بيانات الطالب من الويدجتات.

## 12. ملاحظات التجربة الثانية ✅ (الجلسة ٢)
- **الحركة**: لا نحرّك محتوى الشاشات عند فتحها (أُلغي `Stagger` من `Screen`) — حركة الانتقال وحدها تكفي، والحركتان معاً كانتا تبدوان بطيئتين. الانتقال بين الشاشات `ios_from_left` (٢٠٠ms مع حركة خفيفة للشاشة الخلفية) بدل `slide_from_left` (٤٠٠ms). اللوحات السفلية والتنبيهات توقيت ٢٢٠ms بلا نوابض متأرجحة.
- **الدردشة**: الرسالة تظهر فوراً قبل رد الخادم («يُرسل») ثم تُستبدل بالمحفوظة بنفس المفتاح (بلا وميض). أُلغيت حركة إعادة ترتيب الفقاعات (LinearTransition) لأنها تتقطع مع القائمة المقلوبة.
- **المقدمة** (~٢٫٢ ثانية): كل الحركة على خيط الواجهة ولا تبدأ إلا بعد اختفاء شاشة البداية الأصلية فعلاً. «سعي» يُكتب من اليمين لليسار بقناع بحافة ناعمة بدل قفزات الكشيدة.
- **قص النقاط**: قيس بـ fontTools: الياء الأخيرة تنزل ٠٫٥٥ من حجم الخط (العناوين) و٠٫٥ (النص) والخط يعلن ٠٫٢٥ فقط. الحل في `T`: `paddingBottom` بمقدار الفرق + `marginBottom` سالب بنفس القيمة (التخطيط لا يتغير). الويدجتات: `paddingBottom` ٠٫٣٢ من الحجم.
- **هدف الطالب**: النجاح / الإعفاء من المواد / الإعفاء العام — يُختار في التسجيل وصفحة الدرجات والإعدادات، يُحفظ على الهاتف (`lib/goal.ts`) بلا تغيير في قاعدة البيانات.
- **تحليل الدرجات** في `packages/shared/src/plan.ts` (`analyzeGrades`): نتيجة واحدة بجمل بسيطة تستخدمها الدرجات والرئيسية والويدجت. الإعفاء العام يحسب كل المواد (المادة بلا درجات = كل امتحاناتها متبقية) ودرجة موحدة لكل امتحان قادم + حد أقل مادة.
- **إدخال الدرجات**: امتحان واحد ← كل المواد في قائمة. «ماذا لو؟» في صفحة المادة.
- **النهائي يغلق الفصل الثاني**: إذا أُدخل النهائي وكان للفصل الثاني شهر واحد، يأخذ ذلك الشهر وزن الفصل كاملاً.
- **الإشعارات بلا حساب Expo**: رمز Firebase المباشر من الجهاز + FCM HTTP v1 في دالة `push` (سر `FCM_SERVICE_ACCOUNT`). رموز Expo ما زالت مدعومة إن أُضيف `projectId` لاحقاً.
- **ربط الإشعارات بقاعدة البيانات**: مشغّلات pg_net (migration ١١) بدل Database Webhooks اليدوية. الرابط والسر في جدول `private.settings`.
- **رفع الدوال**: سير عمل `deploy-supabase.yml` من أسرار GitHub (بلا حاسوب). `google-services.json` يُكتب أثناء بناء APK من سر `GOOGLE_SERVICES_JSON` عبر `app.config.js`.
- **الأجهزة اللوحية**: المحتوى بعرض أقصى ٧٢٠ (`MAX_WIDTH`) في الوسط. تكبير خط الهاتف بحد ١٫٣.
- **لوحة التحكم على الهاتف**: شريط علوي + قائمة منزلقة، والجداول تتحول لبطاقات تلقائياً (اسم العمود فوق كل قيمة).
- **شعار الشعبة**: دائرة مسطحة بلون الحبر + حرف الشعبة + نقطة الإعفاء الزرقاء (أُلغي التدرج). **شعار دردشة المدرسة**: شهاب أبيض على الأزرق (إعدادية الشهاب). **مساعد سعي** مثبت أعلى قائمة الدردشة، ومن داخل المحادثة («اسأل مساعد سعي عنها»).

## 13. التخزين والموقع ✅ (الجلسة ٢)
- **التخزين**: Supabase Storage (حاوية `files` خاصة، روابط موقّعة) بدل R2 الذي يطلب بطاقة. `_shared/storage.ts` يبدّل تلقائياً إلى S3 (R2 أو Backblaze B2) إذا أُضيفت أسراره. حد الملف ٥٠ ميغا في المجاني. سير عمل Deploy Supabase يختبر الرفع والتحميل في كل نشر.
- **الموقع**: Firebase Hosting (مشروع `saeyiq`): الموقع التعريفي `saeyiq.web.app` (`apps/site`، HTML/CSS بلا إطار)، ولوحة التحكم تحت مسار غير معلن `/saey-dashboard/` (اختيار صاحب المشروع: مستودع واحد ومسار فرعي). ينشر `deploy-site.yml`.
- **ملف APK للتنزيل العام**: لا يوضع على Firebase Hosting (المجاني ٣٦٠ ميغا يومياً فقط = ٥ تنزيلات، وتجاوزه يوقف الموقع واللوحة). الرابط يُضبط من متغير `DOWNLOAD_URL`.

## 14. المرحلة أ: المؤقت والمساعد ✅ (الجلسة ٣)
- **رنين المؤقت والتطبيق مغلق**: إشعار مجدول من النظام (لا مؤقت داخل التطبيق)، بقناة `timer-alarm` بصوت المنبّه (ALARM) واهتزاز طويل ويظهر على شاشة القفل. صلاحيتا `SCHEDULE_EXACT_ALARM` و `USE_EXACT_ALARM` حتى يُستخدم المنبّه الدقيق (بدونهما قد يتأخر أندرويد الإشعار دقائق). الحالة تُحفظ كـ «وقت الانتهاء» في AsyncStorage فيبقى الوقت صحيحاً بعد إغلاق التطبيق. بعض الهواتف (شاومي/هواوي) تحتاج «بلا قيود» للبطارية: زر في الشاشة يفتح الإعدادات.
- لم نستخدم خدمة أمامية (foreground service) بعدّاد في الإشعارات: تحتاج مكتبة أصلية إضافية وصلاحيات خاصة، والمنبّه الدقيق يكفي للرنين.
- جلسة التركيز تُسجَّل كاملة عند انتهائها، أو جزئياً عند «إنهاء» مبكر إن تجاوزت ٥ دقائق.
- **المساعد يعرف الطالب**: التطبيق يرسل ملخص درجاته وهدفه (`studentBrief` في الحزمة المشتركة، نفس حسابات شاشة الدرجات)، والخادم يضيف اسمه وشعبته ودقائق دراسته من قاعدة البيانات. يُستخدم فقط في أسئلة الوضع والنصيحة، لا في أسئلة المنهج.
- **تنسيق الملزمة**: Markdown + `==تظليل==` + صناديق `>` للقوانين + LaTeX. نفس HTML يُستخدم للعرض ولـ PDF (expo-print). المعادلات داخل السطر باتجاه LTR معزول حتى لا تنقلب في النص العربي.

## 15. ملاحظات تجربة apk-17 ✅ (الجلسة ٣)
- **سرعة المساعد**: التحية والكلام القصير ← النموذج الخفيف بلا تفكير ولا بحث في الملازم (~١ ثانية). البقية: تفكير «low»، والنموذج المشغول (503/429) يُتخطى فوراً لدقائق بدل إعادة المحاولة في كل سؤال. السجل آخر ٨ رسائل مختصرة.
- **تكرار الأجوبة القديمة**: السبب أن السؤال وجوابه كانا يُحفظان بنفس الوقت تماماً، فيختلط ترتيبهما عند القراءة ويظن النموذج أن السؤال القديم لم يُجب. الآن وقتان مختلفان، وترتيب احتياطي (السؤال قبل الجواب) في الخادم والتطبيق، وتعليمات «أجب عن آخر رسالة فقط».
- **فهرس التطبيق**: عند طلب محاضرة/ملزمة/أسئلة يُرفق للنموذج فهرس مختصر (حسب المادة والأستاذ إن ذُكرا)، ويرد برمز `[[lecture:ID]]` يعرضه التطبيق بطاقة تُفتح. لا يُرفق في الأسئلة العادية (توفيراً).
- **رموز داخل الإجابة**: `[[lecture|document|question_set:ID]]`، `[[developer]]` (بطاقة المطوّر وروابطه)، `[[pdf:ID]]` (رسالة «تم التحويل إلى PDF»).
- **PDF**: طباعة أندرويد تعمل بلا JavaScript، فكانت الصفحة فارغة إلا العنوان. الآن Markdown والمعادلات تُحوَّل داخل التطبيق (marked + KaTeX + mhchem) إلى HTML جاهز. نفس المحوّل للعرض داخل الإجابة.
- **تنسيق المواد**: كتل ```شعر (صدر // عجز)، ```قرآن (البسملة، الآيات بخط أميري، المرجع، «صدق الله العظيم» صغيرة)، ```حديث، والجمل الإنكليزية من اليسار تلقائياً.
- **المشاركة**: نوعا مرفق جديدان: `answer` (نص الإجابة كاملاً داخل المرفق، فلا يحتاج صلاحية على محادثات المساعد) و `file` (PDF مرفوع في مجلد المحادثة). عارض PDF داخل التطبيق بـ pdf.js (من الإنترنت) مع حفظ ومشاركة وإرسال لدردشة.
- **المؤقت**: نغمة منبّه خاصة ٢٠ ثانية (`assets/sounds/saey_alarm.wav`) على قناة جديدة `timer-alarm-2` (إعدادات القناة لا تتغير بعد إنشائها). العد التنازلي في الستارة عبر وحدة أصلية صغيرة `modules/saey-timer` (Kotlin) تستخدم عدّاد أندرويد المدمج (Chronometer) فيتحدث بلا تشغيل التطبيق، ويختفي وحده عند الانتهاء.
- **التحديث من داخل التطبيق**: رقم النسخة = رقم بناء GitHub (`APK_BUILD` ← versionCode). التطبيق يقرأ `saeyiq.web.app/download.json`، وإن وجد رقماً أكبر يعرض «تحديث جديد متاح» فيحمّل الملف ويفتح شاشة التثبيت (يُثبَّت فوق القديم لأن التوقيع ثابت، فلا تضيع البيانات). لم نستخدم EAS Update لأنه يحتاج حساب Expo. **شرط**: تحديث رقم النسخة في `apps/site/download-config.json` بعد رفع الملف على Dropbox.

## 16. الحدود والمحتوى ✅ (الجلسة ٣)
- **مفاتيح Gemini متعددة**: بطلب صاحب المشروع (رفض الدفع ٢٠$ شهرياً، ورأى أن Groq وغيره ضعيفة بالعربي): ٤ مفاتيح للطلاب (`GEMINI_API_KEY`, `_2`, `_3`, `_4`) + مفتاح للوحة التحكم. نبّهناه أن شروط Google تمنع «التحايل على الحصة» بعدة مشاريع وأن بعض المفاتيح قد تُوقف؛ القرار له. التنفيذ: كل مفتاح يبدأ بنموذج مختلف (طلبه)، المشغول أو الموقوف يُتخطى تلقائياً، والتحية تجرب الأسرع على كل المفاتيح. لا نخفي مصدر الطلبات ولا نغيّر الخوادم للتمويه.
- **ملفات Gemini (PDF) مرتبطة بالمفتاح** الذي رفعها: تُحفظ كـ `k<رقم>|<رابط>` وتُقرأ بنفس المفتاح.
- **توفير الحصة**: التحية لا تُحسب من رصيد الطالب، والإجابات على الأسئلة المستقلة (أول سؤال في محادثة، ليس عن الطالب نفسه ولا يطلب محتوى) تُحفظ ٣٠ يوماً في `ai_cache` وتُعاد بلا استهلاك.
- **مساعد المحتوى** (دالة `content-ai`، مفتاح لوحة التحكم): روابط يوتيوب (قائمة/قناة/فيديو) ← تصنيف بالذكاء الاصطناعي (مادة، فصل موجود أو جديد، أستاذ موجود أو جديد، رقم، عنوان مرتب، تخطي الإعلانات) ← مراجعة ← إضافة. ملفات PDF ← أول ٤ صفحات ← تصنيف ← مراجعة ← حفظ وفهرسة. المشرف يراجع دائماً قبل الحفظ.
- **فهرسة المحاضرات بالدقيقة**: Gemini يشاهد الفيديو من رابط يوتيوب بأجزاء ١٠ دقائق (حد وقت الدالة)، بدقة منخفضة وصورة كل ثانيتين ← `lecture_topics` + مقاطع في `content_chunks` (`source_type='lecture'`, `start_sec`). المساعد يضع `[[lecture:ID@ثواني]]` فتُفتح المحاضرة عند الدقيقة، وشاشة المحاضرة تعرض المواضيع وتنتقل إليها.
- **قوائم يوتيوب**: مفتاح YouTube Data API إن وُجد، وإلا قراءة صفحة القائمة (أقل ثباتاً).
- **التخزين**: صاحب المشروع سيضبط Oracle Object Storage بنفسه لاحقاً (S3 متوافق — الكود جاهز عبر `S3_ENDPOINT`, `S3_REGION` والمفاتيح).
- **migrations من ١٢ فما بعد** تُطبَّق تلقائياً في كل نشر (Deploy Supabase) لأنها آمنة لإعادة التشغيل. `match_chunks_v2` بدل تعديل الدالة القديمة.

## 17. التحديث التلقائي ✅ (الجلسة ٣)
- بدل رفع APK يدوياً على Dropbox: كل بناء ينشر `saey.apk` في مستودع GitHub **عام** `dagg-iq/saey-releases` (المستودع الأساسي يبقى خاصاً، فروابط نسخه لا تعمل للطلاب).
- البناء نفسه يكتب الرابط والرقم في `apps/site/download-config.json` (commit من saey-bot) ويشغّل Deploy Site، فيظهر «تحديث جديد متاح» بلا أي خطوة يدوية.
- المفتاح `RELEASES_TOKEN` (fine-grained، Contents فقط، على `saey-releases` فقط) في GitHub Secrets. بدونه يبقى البناء كما كان (Releases الخاصة فقط).

## 18. الجلسة ٤: التوقيع، الفهرسة القوية، المواد، الهوية ✅
- **مفتاح التوقيع الخاص**: سير عمل `Create Signing Key` ينشئ مفتاح RSA ٤٠٩٦ بصلاحية ١٠٠ سنة، ويحفظه **مشفّراً** (AES-256 + PBKDF2) في `signing/saey-release.keystore.enc` بالجملة السرية `SIGNING_PASSPHRASE` (سر في GitHub). `build-apk.yml` يفكه ويضبط التوقيع عبر `scripts/apply-signing.js` بعد prebuild. إن وُجد الملف ولا يوجد السر يفشل البناء بدل أن يوقّع بمفتاح مختلف بصمت. قبل إنشائه تبقى النسخ بمفتاح Expo العام. **تغيير التوقيع يعني أن النسخ المثبتة بالمفتاح القديم لا تقبل التحديث فوقها**: كل طالب يحذف النسخة القديمة ويثبت الجديدة مرة واحدة (تبقى بياناته في الخادم). لذلك الأفضل قبل نشره لزملائه. ضياع الجملة أو الملف = إعادة تثبيت للجميع.
- **فهرسة الكتب والملازم بأقوى نموذج**: تُنفَّذ مرة واحدة فتُفضَّل الجودة: ٦ صفحات في الطلب (بدل ١٠)، دقة صور عالية (`MEDIA_RESOLUTION_HIGH`)، تفكير `low`، تعليمات نسخ حرفي بلا تلخيص، وسلسلة النماذج الرئيسية (الأقوى أولاً) بدل الخفيفة. إعداد `ai.ingest_model` (في إعدادات اللوحة) يُجرَّب أولاً (مثلاً نموذج Pro إن كان متاحاً لمفتاحك). «فحص المفاتيح» صار يعرض أسماء النماذج المتاحة لمفتاح اللوحة. نماذج Pro غير مجانية عادة (429 فتُتخطى تلقائياً).
- **المواد والكتب**: مادة اللغة الكردية (`kurdish`)؛ الإنكليزي كتابان: «كتاب الطالب» و«كتاب النشاط»؛ العربي جزءان: «الجزء الأول (قبل نصف السنة)» و«الجزء الثاني (بعد نصف السنة)» (migration ١٣). حسابات الدرجات تعمل على أي عدد مواد.
- **هوية المساعد**: اسمه «سعي AI». أسئلة الهوية («من أنت/أي نموذج») تُجاب بنص ثابت من الخادم بلا استدعاء نموذج، وأي جواب يذكر شركة أو نموذجاً آخر يُستبدل. مفتاح الكاش صار `v2|…` حتى لا تعود أجوبة قديمة («أنا من جوجل»).
- **اللوحات السفلية**: Modal في أندرويد نافذة منفصلة يظهر فيها شريط التنقل من جديد (التطبيق يخفيه) فتبقى فجوة تحت اللوحة. صارت `Sheet` تُرسم في طبقة داخل نافذة التطبيق (`components/portal.tsx`) فتلتصق بالحافة.
- **تحميل التحديث**: حالة عامة (`useDownload`) بشريط تقدم ونسبة، تبقى لو أُخفيت النافذة، وإشعار تقدم يُحدَّث في مكانه وإشعار عند الاكتمال يفتح «عن التطبيق». التحميل مبني على `DownloadTask` من expo-file-system؛ يستمر ما دام أندرويد يُبقي التطبيق حياً (لا خدمة أمامية أصلية).
- **الإشعارات الفورية**: صورة كبيرة (غلاف الخبر أو صورة الرسالة) برابط مؤقت ٢٤ ساعة، نص الخبر كاملاً (حتى ٦٠٠ حرف) ليتوسع بالسحب، أولوية عالية وظهور على شاشة القفل، وأيقونة صغيرة بشعار سعي بدل المربع الأبيض (أيقونة أحادية اللون من `android-icon-monochrome.png`). إشعار العد التنازلي: أيقونة الشعار، نص موسّع، «سعي» تحت العنوان.
- **عن التطبيق**: شاشة جديدة `/about` (النسخة، ما هو سعي، المزايا، التحديثات، المطوّر وروابطه، موقع، مشاركة).

## 19. الجلسة ٥: تحويل الورق، عارض PDF داخلي، نوافذ بتصميم سعي ✅ (الكود — لا بناء حتى يطلب صاحب المشروع)
- **تحويل ورقة إلى PDF لكل الطلاب** (`/scan`، دالة `scan-convert`): صور (حتى ٨، ١٠ للمشرفين) ← Gemini يعيد بناء كل صفحة بـ HTML بنفس تنسيقها (محاذاة، جداول، ترقيم حرفي، خطوط الإجابة) ← التطبيق يقصّ الأشكال من الصورة الأصلية (`data-box` بإحداثيات ٠–١٠٠٠) ويحسب المعادلات بـ KaTeX ثم يطبعها PDF. الصور تُرسل مباشرة (لا تُخزَّن)، فلا يحتاج الطالب صلاحية رفع. تُحسب من رصيد المساعد اليومي (الأدمن بلا حد). **ما لا نضمنه**: مطابقة بالبكسل (إعادة بناء بالذكاء الاصطناعي لا نسخ)، ودقة الأشكال المعقدة؛ لم تُجرَّب مع Gemini فعلياً بعد.
- **شاشة النتيجة** (`/scan-result`): معاينة، إرسال إلى شعبة/شخص كـ PDF أو صور، حفظ كـ PDF أو صور في مجلد، وللمشرفين «إلى الأسئلة» (متوقعة/امتحانات سابقة) بصيغة PDF فقط (`content_md` فارغ، يُنشر مباشرة).
- **كل ملفات PDF تُفتح داخل التطبيق** (`/pdf`): `openPdf(key, title)` صار يوجّه للعارض الداخلي بدل تطبيق خارجي (ملازم المواد، الأسئلة، المستند). pdf.js **مضمّن في التطبيق** (`lib/pdfjs-source.ts` مولَّد بـ `scripts/gen-pdfjs.js`، ١٫٤ ميغا) فيعمل بلا إنترنت (كان يحمّله من cdnjs) والعامل في الخيط الرئيسي. العارض يصدّر الصفحات صوراً للإرسال والحفظ، وتوجد معاينة الصفحة الأولى (`PdfThumb`) في شاشة المستند.
- **نوافذ التنبيه بتصميم سعي**: `lib/dialog.tsx` (نفس توقيع `Alert.alert`) يحل محل نافذة النظام في كل الشاشات، ومعها عارض الصور صار في الطبقة نفسها (لا Modal). في لوحة التحكم: `askConfirm`/`askText` بدل `confirm`/`prompt`. ما لا يمكن تغييره: نوافذ النظام (اختيار المجلد، المشاركة، الصور، إذن الإشعارات).
- أُزيلت عبارة «صُنع بحب» من التطبيق والموقع.
- **قاعدة الجلسة**: لا نبني APK إلا بطلب صاحب المشروع. نعمل commits بـ `[skip ci]` فلا تعمل أي سير عمل (الدوال والهجرات تُنشر بتشغيل Deploy Supabase يدوياً، والتطبيق بـ Build APK يدوياً).

## 20. الجداول وحفظ التفضيلات على الحساب ✅ (الجلسة ٥ — الكود، بلا بناء)
- **الجداول** (migration ١٤): `schedules` (عنوان، وصف، نوع weekly/exam/custom، شعبة أو للكل، منشور، ترتيب) + `schedule_items` (يوم ٠–٦ أو تاريخ، ترتيب/رقم حصة، من/إلى، مادة أو عنوان حر، أستاذ، مكان، ملاحظة). الطالب يقرأ المنشور لشعبته أو للكل فقط، والمشرفون يكتبون (RLS مُختبَر). أي عدد من الجداول: حصص، امتحانات شهرية، نصف السنة، أي جدول مخصص.
- **الذكاء في عرض اليوم** (`packages/shared/src/schedule.ts`، ١٣ اختباراً): يُبرز التطبيق جدول **اليوم** إن كان الوقت قبل ساعة التحويل (٩:٠٠ افتراضياً، حتى لو الطالب مستيقظ في ٧)، وبعدها **يوم الدوام التالي** (يتخطى الجمعة والسبت). أيام الدوام وبدايته ونهايته وساعة التحويل في `app_settings.schedule` تعدّلها اللوحة. أثناء الدوام تُبرز الحصة الجارية والتالية. في الامتحانات يُبرز الأقرب مع «بعد N أيام».
- **في التطبيق**: «المزيد ← الجداول» (قائمة مرتبة حسب النوع)، وبطاقة «جدول الحصص» في الرئيسية، وشاشة الجدول: يوم/أسبوع كامل، اليوم المبرز بلون سعي الأزرق.
- **في اللوحة** (صفحة «الجداول»): إنشاء/تعديل/نسخ/حذف/نشر، محرر حصص لكل يوم (عدد الحصص، مادة أو عنوان حر، أستاذ، أوقات)، «أوقات تلقائية» (بداية + مدة + استراحة)، نسخ يوم لبقية الأيام، محرر مواعيد للامتحانات والجداول المخصصة، وزر **طباعة A4 عرضية** بتصميم سعي (شريط علوي بتدرج أزرق، شعار، جدول بزوايا مدورة وصفوف متناوبة، تذييل) — مُختبَر بتحويل الصفحة إلى PDF بمقاس A4 عرضي من صفحة واحدة.
- **التفضيلات على الحساب** (`profiles.prefs jsonb`): كان الهدف (نجاح/إعفاء) والمظهر وإعدادات المؤقت ومظهر الويدجتات في ذاكرة الهاتف فقط، فتضيع عند الخروج أو حذف التطبيق. الآن تُقرأ من الحساب عند الدخول (قبل ظهور الشاشات) وتُطبَّق، وكل تغيير يُحفظ على الحساب بعد ٠٫٦ ثانية (مع إعادة محاولة، وإرسال المعلّق قبل الخروج). ما كان محلياً فقط عند أول دخول بعد التحديث يُرفع للحساب. عند الخروج تُمسح محلياً حتى لا يرثها حساب آخر على نفس الهاتف. الباقي كان على الحساب أصلاً: الدرجات، المهام، جلسات الدراسة، التقدم، الإشعارات.

## 21. العمل بلا إنترنت ✅ (الجلسة ٥ — الكود، بلا بناء)
- **السبب**: عند فتح التطبيق بلا إنترنت بعد انتهاء صلاحية الجلسة (ساعة) كان supabase يحاول تجديدها فيفشل، فيُعامَل الطالب كزائر ويُرمى لشاشة الدخول. وحتى لو فُتح، كانت كل القراءات تفشل.
- **الجلسة**: إن تعذّر التجديد نقرأ الجلسة المخزنة مباشرة (`sb-<ref>-auth-token`) ونفتح التطبيق بها، ونعيد محاولة التجديد كل ١٥ ثانية؛ إن رُفضت فعلاً نعود لشاشة الدخول.
- **القراءات** (`lib/offline-fetch.ts`، اختبار `e2e/offline-fetch-test.js`): طبقة fetch تحت عميل supabase تحفظ كل قراءة ناجحة (GET/HEAD ودالة `my_conversations`) وتعيدها عند انقطاع الاتصال أو بطئه (١٥ ثانية). مستثنى: الرسائل ومحادثات المساعد وفهارس المحتوى. حد أقصى ١٥٠ استعلاماً و٣ ميغا (الأقدم يُحذف). لا نحفظ ردود المفتاح العام (بلا جلسة). تُمسح عند تسجيل الخروج. الكتابة بلا إنترنت تفشل برسالة (لا نخدع الطالب). شريط «بدون إنترنت — تعرض آخر ما حُفظ».
- **يعمل بلا إنترنت**: الرئيسية، الدرجات، المواد والفصول وقوائم المحاضرات والملازم، الجداول، المهام، الأخبار، الإعدادات، الملازم المحمّلة (في عارض التطبيق، مع pdf.js المضمّن) وأجوبة المساعد بمعادلاتها (KaTeX مضمّن `lib/katex-css.ts`). **لا يعمل**: فيديو يوتيوب، المساعد، تحميل ملف جديد، الدردشة الحية، أي حفظ.
- **الملازم والكتب**: زر «تحميل للهاتف فقط» بشريط تقدم ونسبة، يُكتب في ملف مؤقت ثم يُنقل (لا يبقى ملف ناقص يُحسب محفوظاً)، وتُفتح داخل التطبيق.
- **أول مرة**: القراءات تُحفظ وأنت متصل، فلا بد من فتح الشاشات مرة بإنترنت قبل أن تعمل بلا إنترنت.

## 22. تنسيق التواريخ في الجداول وطباعة جديدة ✅
- التواريخ بالأرقام يوم/شهر والسنة تحتها أصغر (٩/١٠ فوق ٢٠٢٦) بدل أسماء الأشهر، في التطبيق والطباعة (`dateParts` في shared). الأرقام مشرقية كبقية التطبيق.
- طباعة A4 عرضية بتصميم أغنى: ترويسة بتدرج أزرق وزخرفة وشعار في بطاقة بيضاء، حصص كبطاقات ملوّنة (لون ثابت لكل مادة) مع أسماء الأساتذة، مواعيد كبطاقات بصناديق تاريخ ملوّنة، مفتاح ألوان، وتذييل. صفحة واحدة دائماً (اختُبر ٦ حصص و٦ امتحانات).

## 23. النماذج وأقسام اللوحة ✅ (الجلسة ٥ — الكود، بلا بناء)
- **بحث النماذج** (مصادر ثانوية، لا صفحة Google الرسمية المحجوبة من السحابة): 3.8 Flash سعره التمهيدي ٠٫٧٥$ إدخال / ٣٫٧٥$ إخراج لكل مليون حتى ٣١ ديسمبر ٢٠٢٦ ثم ١٫٥ / ٧٫٥؛ 3.1 Pro ٢$ / ١٢$ ولا يتوفر في الطبقة المجانية؛ الطبقة المجانية لـ Flash وFlash-Lite فقط. في مقاييس مستقلة 3.8 Flash يساوي أو يتفوق على 3.1 Pro في أغلب الاستدلال (مؤشر Artificial Analysis ٤١ مقابل ٣٠)، وتجربة برمجية واحدة عكست ذلك. **القرار**: 3.8 Flash أولاً لكل شيء (الدردشة، الفهرسة، التحويل)، و Pro غير لازم ولا نربط بطاقة دفع.
- **التفكير الأعمق**: متاح في الـ API عبر `thinkingLevel` (minimal / low / medium / high). وضع «Deep Think» الخاص بتطبيق Gemini غير معروض في الـ API على حد علمنا. `ai-chat` صار يختار المستوى حسب الطلب: توليد أسئلة وامتحانات وحل مسائل ← `high` (وحد إخراج ٢٤٥٧٦ لأن التفكير يُحسب منه)، الشرح والمقارنة والتعليل ← `medium`، الباقي `low` (سريع). تغيير المستويين من إعداد `ai.thinking_hard` و `ai.thinking_explain`. الثمن: جواب أبطأ (حتى نصف دقيقة) واستهلاك أكبر من حصة المفتاح.
- **Gemini 2.5**: أقدم وأضعف، وموعد إيقافه ١٦ أكتوبر ٢٠٢٦ على الـ API، وحسابات جديدة تحصل على 404 — لا نستخدمه (الكود يحذف أي اسم `gemini-2.` من الإعدادات أصلاً). أُضيف 3.6 Flash لسلسلة الاحتياط.
- **مفتاح لوحة التحكم**: في «حالة المفاتيح» رد 403 «Your project has been denied access» أي أن Google حجبت **مشروع** ذلك المفتاح (ليس خطأ بالكود). الكود يحتاط تلقائياً بمفاتيح الطلاب. الحل: مفتاح جديد من aistudio.google.com بحساب Google يُنشئ مشروعاً جديداً، ثم تحديث السر `GEMINI_ADMIN_API_KEY`.
- **ألوان أقسام لوحة التحكم**: القائمة مقسمة إلى: الطلاب والتواصل (أزرق)، المحتوى التعليمي (أخضر)، الجداول والمتابعة (برتقالي)، النظام (بنفسجي)، بعناوين وعلامات ملوّنة والصفحة الحالية بلون قسمها.

## 24. أي مفتاح يستخدم أي نموذج (توثيق) + أيقونات القائمة
- **الدردشة** (المفاتيح ١–٤، `generate` مع `spread`): قائمة المحاولات مرتبة جولات؛ الجولة الأولى: مفتاح١←3.8، مفتاح٢←3.7، مفتاح٣←3.6، مفتاح٤←3.5 Flash، ثم الجولة التالية بإزاحة نموذج. **كل سؤال يبدأ بالمفتاح ١ و3.8** ولا يذهب للبقية إلا إذا كان (مفتاح،نموذج) مشغولاً (503 ← يُتخطى دقيقتين، 429 ← عشر دقائق) أو أُوقف. أي أنها سلّم احتياط لا توزيع حمل.
- **التحية والأسئلة القصيرة**: نموذج خفيف أولاً على كل المفاتيح بالتناوب: 3.5 Flash-Lite ثم 3.1 Flash-Lite ثم 3.8 ثم 3.5 Flash (تفكير minimal).
- **لوحة التحكم** (مفتاح ٥ ثم مفاتيح الطلاب احتياطاً): كل النماذج على مفتاح اللوحة بالترتيب 3.8 ← 3.7 ← 3.6 ← 3.5 Flash ← 3.5 Flash-Lite ← 3.1 Flash-Lite، ثم ننتقل لمفاتيح الطلاب. (الفهرسة وتحويل الورق والتصنيف). **إصلاح**: مفتاح اللوحة المحجوب (`denied access`) كان يُجرَّب مع كل نموذج قبل الانتقال (٦ طلبات فاشلة لكل عملية)؛ صار يُتخطى ٣٠ دقيقة كالمفتاح غير الصالح.
- إن وُضع `ai.model` في الإعدادات فهو أولاً في السلسلة (الافتراضي 3.8). قيم الإعدادات الفعلية في قاعدة البيانات تُراجع من لوحة التحكم ← الإعدادات.
- **القائمة الجانبية للوحة**: أيقونة خطية لكل تبويب بلون قسمه (تمتلئ للصفحة الحالية)، وشريط التمرير مخفي مع بقاء التمرير.

## 25. توحيد لوحة التحكم مع التطبيق (الأسئلة والأخبار) ✅
- **الأسئلة في اللوحة**: زر «+ من صور (تحويل ذكي إلى PDF)» (`components/ScanConvert.tsx`، `lib/scan-convert.ts`): رفع حتى ١٠ صور وترتيبها ← نفس دالة `scan-convert` ← قص الأشكال من الأصل (canvas) وحساب المعادلات (KaTeX) ← صفحات A4 ← PDF عبر html2canvas + pdf-lib (مكتبتان جديدتان في اللوحة، تُحمَّلان عند الاستعمال فقط) ← معاينة صفحات ← تنزيل PDF أو حفظ ونشر/مسودة كمجموعة أسئلة (`pdf_key`، بلا `content_md`). اختُبر في كروميوم مع رد وهمي: عربي سليم، معادلة، جدول، شكل مقصوص، سطور الإجابة، صفحة A4 واحدة. **الـ PDF صور للصفحات** (النص غير قابل للتحديد) كما في التطبيق (طباعة الهاتف أيضاً صورة/نص مدمج حسب النظام).
- القديم (كتابة نص يدوياً بـ Markdown) بقي كزر ثانوي.
- **الأخبار في التطبيق**: صورة اختيارية (معرض أو كاميرا، قص ١٦:٩، ضغط ١٦٠٠) تُرفع كغلاف `cover_key` كما في اللوحة، وتظهر في قائمة الأخبار وصفحة الخبر.
